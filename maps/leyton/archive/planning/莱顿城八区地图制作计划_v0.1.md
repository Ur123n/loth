# 莱顿城八区地图制作计划 v0.1

制定日期：2026-09-14  
上游规划：`莱顿城八区地图规划_v0.1.md`  
当前阶段：制作准备  
目标：完成八张可运行、可连接、可复用的 48×48 px 俯视 2D 地图，并同步交付分层 PNG、地图 JSON 与 Godot 场景。

## 当前进度

- 2026-09-14：已建立严格正交、固定比例的八图总拓扑 v0.1。
- 拓扑换算固定为 `1 游戏瓦片 = 4 图像像素`，SVG、PNG 与 JSON 同步交付。
- 八图首版工作尺寸与连接方向已经写入拓扑 JSON，仍须经过玩家、马车、门洞及墙顶通行测试后冻结。
- M01 河道已拍板从中心广场南侧绕行；北绕图只保留为归档对照。
- 2026-09-14：已完成八区1:8独立灰盒 v0.1，并为 M01 额外制作北绕/南绕两个候选版本。
- 灰盒共九张单图及一张原生比例总览图；全部占地、折线、出口和 PNG 尺寸校验通过。
- M07→M04→M01 的直连水口已统一到纵坐标第64格；M01 南绕方案已冻结并进入1:1通行测试。

## 一、生产目标与边界

### 最终成果

- M01 中心广场
- M02 城北贵族住宅区
- M03 城南贫民窟
- M04 城西商业区
- M05 北门与城外
- M06 南门与城外
- M07 西门与城外
- M08 东门与城外

每张地图必须具备：

1. 完整地表、道路、水体、建筑、物件和前景遮挡层；
2. 碰撞、导航、高度、出生点和场景出口数据；
3. NPC 刷新位、巡逻路线和事件预留点；
4. 与相邻地图方向一致的连接触发器；
5. 开放、宵禁、剧情封锁三种城门状态所需接口；
6. 同名分层 PNG、JSON、Godot `.tscn` 与预览图。

### 本轮不包含

- 普通城东住宅区独立地图；M01 与 M08 之间采用抽象路程切换。
- 大量可进入室内场景；首轮只制作外观、入口和室内切换预留。
- 城内常态大规模战斗地图改造；优先支持探索、对话和潜行调查。
- 真实人口规模的一比一城市复刻。

## 二、已冻结的视觉与设定基线

- 城墙：深青色石砖，配煤烟、潮痕、磨损和修补色差。
- 中心地标：健硕、肌肉感明确的太阳神像，低头悲悯地俯视世人。
- 南区：高压迫度，大量棚屋和违建，杂乱、无序、拥挤，但关键路径必须可辨识。
- 城主：罗兰·恩索菲尔德。
- 家徽：银底黑边盾徽；无门黑色方塔立于三道暗金麦穗田垄之上，塔顶悬小型银色八芒星。
- 城墙可登，门楼、墙梯、巡逻道和城垛均为实际可通行空间。
- 河流东西贯城、绕开中心广场，并在西侧汇入大型灌溉湖。
- 主焚尸场位于 M03 城南贫民窟靠城墙一侧。

以上内容进入视觉生产后不随意变更；确需修改时，先更新上游规划，再评估八图影响范围。

## 三、总体制作策略

采用“全城低成本验证 → 三图纵向切片 → 两组成对城区 → 东门补齐 → 全城统一”的顺序。

```text
阶段 0  规格锁定与资源准备
   ↓
阶段 1  八图 1:8 缩略灰盒与连接验证
   ↓
阶段 2  M01 → M04 → M07 首条完整切片
   ↓
阶段 3  M02 ↔ M05 北区组合
   ↓
阶段 4  M03 ↔ M06 南区组合
   ↓
阶段 5  M08 东门与抽象住宅区连接
   ↓
阶段 6  NPC、状态、氛围与性能整合
   ↓
阶段 7  八图联调、QA 与正式交付
```

不允许在全城灰盒连接未通过前批量绘制独占建筑；不允许在门洞、道路和城墙通行尺寸未验证前完成高精度城门美术。

## 四、阶段计划

### 阶段 0：规格锁定与资源准备

目标：建立后续不会频繁变化的生产基线。

任务：

- 固定八图逻辑尺寸、主路宽度、门洞宽度、城墙厚度和切换触发带。
- 建立全城总拓扑图和统一坐标方向表。
- 绘制深青石砖城墙、太阳神像、恩索菲尔德家徽的概念草案。
- 建立城市色板、材质板、建筑比例尺和角色比例尺。
- 整理现有荒野 v1 可复用素材，标出“直接复用、需调色、仅作参考”。
- 建立文件命名、版本号和导出模板。

交付物：

- `leyton_master_topology_v01.png`
- `leyton_scale_guide_v01.png`
- `leyton_palette_material_v01.png`
- 城墙、神像、家徽概念稿各一版
- 资源复用清单与缺失素材清单

验收门槛：四向出口方向无冲突；所有通行宽度能在 48 px 网格上落地；三项核心概念具有统一视觉语言。

### 阶段 1：八图灰盒

目标：用纯色块和占位物完成全城可行走验证，不放正式细节。

任务：

- 为八图制作 1:8 缩略图和 1:1 网格灰盒。
- 标出主路、次路、窄巷、河流、湖泊、城墙、建筑占地和视线地标。
- 标出出生点、出口、门洞、墙梯、巡逻道、桥梁和水门。
- 预留 NPC 聚集区、巡逻路线、潜行绕行线与剧情事件点。
- 按已冻结的 M01 南绕方案验证跨图水位、岸线位置与桥梁需求。
- 用玩家和马车占位体测试转弯、会车、拥堵与回传触发。

交付物：八张灰盒图、全城拼接总览、出口表、尺寸表、灰盒问题单。

验收门槛：

- 八图全部可从正确边缘进出；
- M01 与 M08 抽象路程切换不会立即回传；
- 四个门洞均可供玩家和目标尺寸马车通行；
- 四门均可抵达墙顶巡逻道；
- 河流、水门和西侧灌溉湖连续；
- 不存在不可见死路、强制卡位或无出口封闭区。

### 阶段 2：首条完整切片 M01 → M04 → M07

目标：建立城市核心美术质量基准，并验证最复杂的交通、水运和城防组合。

#### M01 中心广场

- 完成石铺广场、十字主路和中心视觉轴。
- 制作太阳神像、城政厅、太阳神教礼堂、城卫值房和公共水源。
- 布置公告、煤炭配给、税令、失踪与焚尸名册等叙事信息点。
- 控制摊位数量，使其区别于商业区。

#### M04 城西商业区

- 完成车行主街、市场、商会/秤量所、煤仓、粮仓、铁匠铺、药剂铺、旅店和车马栈。
- 完成穿区河道、货运石桥、卸货埠和水闸。
- 验证步行、车流、货物检查和潜行绕行空间。

#### M07 西门与城外

- 完成西门楼、纵向深青石墙、可登城墙和独立水门。
- 完成灌溉湖、堤岸、麦田、灌渠、煤车待检区、商队停车场和修车棚。
- 完成步行与车流分道以及西部世界道路出口。

本阶段共享素材：城市石路、城墙套件、河岸/湖岸、水闸、货运桥、市场物件、煤粮物流物件、成熟麦田和家徽应用件。

验收门槛：三图可连续游玩；视觉密度由中心向西递增；水系不断裂；西门三种状态可切换；家徽、地方封条和皇室军需封条层级清楚。

### 阶段 3：北区组合 M02 ↔ M05

目标：建立低密度、高秩序、资源充裕的阶层样板。

任务：

- 制作 2—3 座宅邸、会客所/军官俱乐部、私家马厩、受保护水源和守卫岗亭。
- 制作北门楼、规整大田、果园或牧草地、石砌田界和税粮车道。
- 统一宽直道路、修整石材、整洁排水和有棚煤堆的视觉语言。
- 布置贵族、管家、仆役、家庭卫兵、医生和送货人刷新位。

验收门槛：M02 与 M03 即使不看 UI 也能迅速区分；北门秩序最好；庄园农业与城市粮食体系具有视觉联系。

### 阶段 4：南区组合 M03 ↔ M06

目标：在高压迫环境中保持可玩性和居民生活可信度。

任务：

- 制作棚屋、违建木屋、窄巷、共用灶、晾晒绳、破损排水沟和积水。
- 制作施粥点、孤儿救济点、廉价旅舍、灰烬收集点和尸体登记棚。
- 将焚尸场作为完整大型建筑制作：收尸门、登记间、煤仓、炉房、烟囱、骨灰室、隔离院和防火净空。
- 制作南门楼、小块佃田、菜圃、牲畜栏、难民棚、劳工集散和伤病隔离棚。
- 用烟囱轮廓建立 M03 与 M06 的跨图视觉联系。

验收门槛：压迫感主要来自密度、遮挡、材质和空间秩序，而非无差别堆垃圾；主通路与关键设施可识别；消防、追逐和潜行死角均为有意设计。

### 阶段 5：M08 东门与城外

目标：补齐四门系统，并验证未制图住宅区的抽象连接。

任务：

- 制作东门楼、东西向军用出城通道和墙顶连接。
- 制作谷物/豆类轮作田、磨坊或风车、东部驿道。
- 制作河流入城水门并与既定城内河道方向对应。
- 为 M01→住宅区抽象路程→M08 制作过场、出生点和回传保护。

验收门槛：玩家明确感知中间存在普通住宅区，而不是 M01 与东门物理相邻；东门具备独立辨识度但仍属于同一城防体系。

### 阶段 6：角色、状态与氛围整合

目标：让八图从静态场景变为可运行城市。

任务：

- 首版按每图 15—25 名同屏 NPC 预算配置刷新点，M04 采用分时刷新制造繁忙感。
- 配置官吏、修士、城卫、贵族、仆役、商人、工匠、苦工、难民和农民等基础职业。
- 配置巡逻、值守、排队、搬运、耕作、交易和救济动作。
- 添加白天、夜间、宵禁和剧情封锁状态。
- 添加河流、湖面、炉火、烟囱、铁匠火星、旗帜和灯光效果。
- 为重要设施预留交互、任务和对话锚点。

验收门槛：关键通路不会因 NPC 堵死；状态切换不破坏导航；宵禁与封锁具有明确视觉和行为反馈。

### 阶段 7：全城联调与交付

任务：

- 八图连续跑图与反向跑图。
- 检查出生点、回传触发带、门洞、桥梁、墙梯、城墙巡逻道和水门。
- 检查碰撞、导航、遮挡、Y 排序、屋顶淡出和越界区域。
- 检查低分辨率辨识度、色板统一、材质重复和视觉噪声。
- 检查同屏 NPC、动画、水体和粒子性能。
- 校验 PNG、JSON 与 `.tscn` 内容一致性。
- 生成八图总览、逐图预览、QA 报告和已知问题清单。

最终验收：八张地图在无编辑器手工补操作的情况下可加载、可连接、可寻路、可切换状态，并满足上游规划中的必备建筑与世界规则。

## 八、质量门槛

### 视觉

- 48×48 网格对齐，像素缩放使用最近邻。
- 八图共用统一色板、光源方向、描边强度和建筑比例。
- 深青石墙在草地、石路、泥地和夜间均保持清晰轮廓。
- 太阳神像在正常镜头尺度下仍能读出“低头、悲悯、健硕”三个特征。
- 恩索菲尔德家徽在旗帜、盾牌和封蜡三个尺度上分别制作简化版本。
- 南区压迫感不得以牺牲主路径、交互物和角色可读性为代价。

### 玩法与数据

- 主路 5—7 格、次路 3—4 格、南区巷道 1—2 格。
- 门洞净宽 4—6 格；墙顶巡逻道宽 2—3 格。
- 场景切换带深 2 格，出生点不位于回传带内。
- 所有可见障碍均有一致碰撞；不可见墙只用于明确越界区域。
- 河道、桥梁、水门、墙梯和屋顶遮挡具有明确导航处理。
- 每个 JSON 均能独立描述尺寸、图层、碰撞、导航、出生点、出口、NPC、河流和城门状态。

### 性能

- 首版同屏 NPC 基准为 15—25；M04 优先用刷新时段而非无限增加实体。
- 大型建筑按可见区域拆分渲染层，但保持单一建筑资产定义。
- 水体和环境动画共享图集与材质，避免逐实例复制资源。
- 地图边缘之外不保留大面积不可见装饰和碰撞。

## 十、主要风险与控制

| 风险 | 后果 | 控制方式 |
|---|---|---|
| 八图先各自精绘 | 接口和比例不一致，大量返工 | 先完成全城灰盒和出口表 |
| 城门过早定稿 | 马车、墙顶和状态切换无法落地 | 门楼先用占位体通过 S2 验收 |
| 南区细节过密 | 导航混乱、角色被遮挡 | 先锁主路径与社区节点，再填棚屋 |
| 城墙整张绘制 | 无法跨地图复用和转向 | 通用墙段 Tile 化，门楼保持独立结构 |
| 现有荒野素材直接混用 | 色板、像素密度和岸线接口冲突 | 进入正式图集前统一调色与复核 |
| 独占建筑数量膨胀 | 工期失控 | 先做地标，普通建筑采用受控变体套件 |
| NPC 数量制造繁忙感 | 拥堵与性能下降 | 分时刷新、换色变体和远景动画 |
| PNG、JSON、场景不同步 | 后期无法稳定迭代 | 每图使用同名版本并进行自动校验 |
