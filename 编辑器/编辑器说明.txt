编辑器文件夹说明
================

本文件夹用于通过 Excel 表格注册游戏数据。

工作流程：
1. 用 Excel/WPS 打开并编辑对应表格（新增行 = 新增数据）。
2. 保存表格后，双击 同步表格.bat（或运行 sync_tables.py）。
3. 启动游戏，数据即生效。

表格说明：
- 角色数据.xlsx  -> content/characters/*.tres（队伍四名角色及新角色）
- NPC创建.xlsx   -> content/npcs/*.json（NpcDB 读取）
- 装备创建.xlsx  -> content/equipment/*.json（EquipDB 读取）
- buff创建.xlsx  -> content/buffs/*.json（BuffDB 读取）
- 敌怪创建.xlsx  -> content/enemies/*.json（EnemyDB 读取）

所有表格统一提供美术资源接口（列名与字段对应）：
- 美术图标（icon）：列表/槽位小图，如 res://美术/icons/骷髅.png
- 美术资源（art）：主体贴图/卡面/立绘，如 res://美术/骷髅.png
- 美术动画（animation）：动画或动画场景资源，如 res://美术/animations/骷髅_动画.tres
角色数据.xlsx 另有 立绘（portrait）列。
填写 res:// 路径后，游戏会用对应资源替代色块/文本占位；留空则继续使用占位。

装备创建.xlsx 可选「修正」（mods）列：JSON 数组，实现装备的“有舍有得”机制修正。
示例：[{"type": "attack_damage_pct", "value": 20}, {"type": "defend_bonus", "value": -2}]
表格没有该列时，同步会保留现有 JSON 中的 mods（以 JSON 为准）。
支持的类型见 docs/character/rules.md 第 6 节。

NPC创建.xlsx 扩展字段：
- 美术资源：贴图路径（可空）
- AI：NPC 行为占位（如 待机/巡逻）
- 互动选项：多个选项用 分号（；或;）分隔
- 对话树：JSON 数组文本，格式示例：
  [{"id":"start","text":"对话文本","options":[{"text":"选项A","next":"节点id"}]}]

敌怪创建.xlsx 字段说明：
- 最小血量 / 最大血量：进入战斗时在该范围内随机生成
- 最小攻击 / 最大攻击：攻击伤害在该范围内随机
- 攻击距离 / 移动力 / 敏捷：战斗行动数据
- AI：无（木桩）/ 靠近（近战） / 远离（远程优先保持距离）

buff创建.xlsx 字段说明：
- 阵营：正面 / 负面 / 中立
- 类型：层数增益、层数持续、持续、即时
- 数值 / 基础持续时间 / 每层持续加成（层数无上限）
- 每回合是否衰减 / 触发后是否消失 / 触发时机与触发条件

卡牌通过卡牌编辑器创建（C:\游戏\编辑器\CardEditor，根目录 启动卡牌编辑器.bat 运行）。

注意：
- 四名固定队员同步到 alice/baldwin/dismas/kasha.tres；新增角色用中文名作文件名。
- 角色数据的“力量伤害补正”列对应 GDD：攻击伤害 = 攻击卡面板 * (1 + 补正 * (力量 - 10))。

补充（2026-08-12 测试整理）：
- 物品创建.xlsx -> content/items/*.json（ItemDB 读取，战利品/背包物品）
- 道途创建.xlsx -> content/paths/*.json（PathDB 读取，被动 + 专属初始牌）
- 卡牌编辑器（给予buff）的持续时间填 0 时按 buff 表自动计算：
  层数持续型（中毒/易伤/虚弱）持续时间 = 基础持续 + (层数-1) × 每层持续；
  其余类型使用 buff 表（基础持续（回合））。

- 敌怪小队创建.xlsx -> content/encounters/enemy_packs.json（EnemyPackDB 读取，按强度抽取 3~4 人小队）

- 敌怪小队创建.xlsx 的“成员列表”列：JSON 数组，每项 {"enemy": 敌怪名, "count": 数量, "role": 角色, "leader": 是否首领}；
  角色为 前排/近战/远程/护卫/侧翼/炮灰/首领；同一种敌怪可在不同小队担任不同角色。

卡牌编辑器与卡牌库（content/cards/*.json）保持同步，以卡牌库数据为准：
- 加载时关键词同时识别 keywords 数组与顶层布尔字段（如 小刀 的 derived、吸血 的 lifesteal）；
- 保存时统一写 keywords 数组，并同步顶层字段 derived/lifesteal，保证已有卡信息不丢；
- 编辑器支持全部 15 种逻辑链（覆盖卡牌库当前 12 种），buff 种类运行时从 数据/buffs 加载。

卡牌编辑器自动保存：
- 修改任意字段（费用/荷载/数值/关键词等）后约 0.6 秒自动写回卡牌库，无需手动点“保存卡牌”；
- 状态栏会显示“已自动保存：卡牌名”；新建卡牌仍需点“保存卡牌”创建；
- 写入为原子操作（先写临时文件再替换），避免中断导致卡牌库损坏。

切换卡牌/新建卡牌前，会自动把当前卡未落盘的修改先写入卡牌库（无需等待 0.6 秒防抖），
避免“改完数值点其他卡再回来发现没变”的问题。

确认修改流程：
- 修改任意字段后状态栏提示“⚠ 有未确认的修改”，点击底部「确认修改」按钮写入卡牌库并弹窗确认；
- 切换卡牌 / 新建卡牌 / 关闭编辑器前，已有卡的未确认修改会自动落盘（不丢修改）；
- 新建卡牌需点击「确认修改」才会创建。

删除卡牌采用回收站模式：删除的卡牌移入 卡牌/cards/.trash/，可在文件管理器中手动恢复；
回收站不影响游戏加载（游戏只读取 cards/ 直接子目录的 .json）。

条件判断（逻辑链）：
- 每条逻辑可挂条件：条件类型从 卡牌/conditions.json 加载（下拉选择“无条件”=不挂条件），
  按类型自动显示参数输入框，可勾选“取反”；
- 保存为 effects 项的 condition 字段，Godot 结算时满足条件才执行该效果、不满足跳过；
- 卡面预览/导出会显示“如果…则 …”。

- 卡牌创建.xlsx -> content/cards/*.json（CardDB 读取）
  一行一张卡；“效果列表”列填 JSON 数组（可含 condition），如
  [{"logic":"attack","value":8,"attack_range":1,"condition":{"type":"敌人数量在攻击范围内","count":2}}]；
  “关键词”列填 JSON 数组或 逗号/顿号 分隔；Excel 中删除的行会在同步时从卡牌库移除（回收站不受影响）。
