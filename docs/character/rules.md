# Character 规则

## 1. 基础属性

| 属性 | 说明 |
| --- | --- |
| 力量 strength | 攻击相关 |
| 敏捷 agility | 行动顺序 |
| 耐力 endurance | HP 加成 |
| 意志 willpower | 荷载上限 |

- 初始四属性 10；每升 1 级获得 1 点自由属性点，由玩家在角色面板手动分配（不自动加）。
- 升级经验：全队共享同一份战斗经验（GameState.grant_battle_exp）。

## 2. HP

`base_hp + endurance_hp_bonus × (endurance − 10)`（角色表配置基础 HP 与每点耐力加成）。

## 3. 伤害计算

伤害 = 面板 × 基数 / 100；基数 = 100 + 力量伤害补正 × (力量 − 10)。玩家对敌怪向上取整，敌怪对玩家向下取整。

## 4. 卡组与技能库

- 每名角色有独立卡组（deck，上限 20 张）与技能库（skill_library）。
- 启动补齐：至少 5 打击 + 5 防御，其余用基础牌补齐到 20 张。
- 道途专属初始牌进入技能库与卡组（幂等，不重复添加）。
- 技能光点（大世界）可为当前角色学习技能（如“冲锋”）。

## 5. 道途（PathData）

- 每名固定角色有一个道途：艾莉丝→梦魇行者、鲍德温→孢子卫士、迪马斯→侠盗、卡莎→解剖学者。
- 道途提供：基础被动（PassiveData：trigger_timing/value）+ 专属初始牌（starter_cards）+ 专属装备/事件/技能树接口（预留，未实现）。
- 被动结算在 BattleManager（如 沉梦：回合开始 2 格挡；孢子再生：结束回合恢复 1 HP；侠盗本能：首回合多抽 1；药理精通：攻击使目标中毒）。

## 6. 装备与物品

- 装备不是单纯的数值提升（GDD 第 14 节），而是「有舍有得」的机制修正：
  每件装备携带 `mods` 修正列表，正修正为得（收益）、负修正为舍（代价），至少各一条；
  穿戴后叠加进角色合并属性与战斗计算。
- 装备部位：头部/身体/腿部/足部/首饰1/首饰2/左手武器/右手武器（8 槽）。
- 穿/脱流程：背包点击装备物品穿到当前角色（槽位被占时旧装备自动卸下放回背包）；
  装备面板点击已穿装备卸下（放回背包）。装备随存档持久化（save version 3，旧档缺省为空）。
- 修正类型（`mods` 条目：`type` + `value`，属性修正另有 `stat`）：

  | type | 效果 |
  | --- | --- |
  | stat | 力量/敏捷/耐力/意志力 ±N（HP/伤害基数/行动顺序/荷载容量派生） |
  | max_hp | 生命上限 ±N |
  | initiative | 行动值 ±N（行动顺序） |
  | load_capacity | 卡牌荷载容量 ±N（意志力派生） |
  | move_points | 每回合移动力 ±N |
  | attack_range | 攻击范围 ±N（卡牌目标射程） |
  | attack_damage_pct | 攻击伤害 ±% |
  | defend_bonus | 防御卡获得格挡 ±N |
  | draw_modifier | 每回合抽牌 ±N |
  | energy_modifier | 每回合费用 ±N |
  | block_on_turn_start | 回合开始获得 N 格挡 |

- 合并规则：面板与战斗使用「基础值 + 装备修正」的合并属性。
  生命上限 = 基础 HP + 合并后耐力×耐力收益 + max_hp 修正；
  伤害基数 = 100 + 力量伤害补正×(合并后力量−10)，再乘 (100+攻击伤害%)/100；
  行动值 = 合并后敏捷 + 行动值修正 + 随机 ±8；荷载容量 = 合并后意志力 + 荷载修正。
- 内容来源：content/equipment/*.json 的 `mods` 字段（编辑器/装备创建.xlsx「修正」列同步，表格无该列时保留 JSON）。
- 物品：背包单位，按形状（1x1/2x1/1x2/3x1/2x2/L）占格；拾取时 first-fit 检测空位。
- 装备/物品数据字段：name/description/slot/stats 等，来自 content/equipment/、content/items/（Excel 同步）。
