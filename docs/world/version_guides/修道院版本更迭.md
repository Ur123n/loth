## 2. 不变项与非技术要求

纯贴图版本维持：48px=1米、正交方格与正交斜投影、48×58地基、放置格、锚点、南门两格通道、露天中庭、碰撞/通行掩码、12个地图标记和对外连通。

12标记：spawn、gate、story_trigger、skill_light、battle_trigger、church、cloister、bell_tower、hospice、crematory、herb_garden、highland_pass。名称、位置、用途都纳入快照，不仅检查数量。

建筑身份为高原边境守焰修院：教堂、钟塔、回廊、水井、医舍、焚尸服务、孤儿与旅人收容、厨房司务、药草园和防护门楼。保持神圣与腐朽并存、低饱和石材与旧木、火作为叙事焦点；院落与生活动线可读。

贴图更换可改变材质与装饰细节；明显改变建筑轮廓或主建筑身份时先给差异草稿确认，不能用一张普通会堂外观替掉整座修院。

## 3. 路线A：更换贴图与材质（默认推荐）

1. 建立revision，备份spec、全部逻辑掩码、现有三层源/显示图、Prefab和活动地图；记录12标记及门/中庭通行基线。
2. 在候选场景复用现有建筑位置、逻辑和遮挡分区。先制作2400×2880统一坐标的视觉几何稿；旧贴图是风格/比例参考，不是必须保留的最终材质。
3. 首件选南门楼或中庭一翼。对照角色检查石缝尺度、门宽、平行线和材质明度，确认后扩展北翼、教堂、回廊与侧翼。
4. 用内置imagegen生成独立材质，保存原图/参考/提示词/哈希。以灰盒alpha控制显示，逻辑画布显式设为2400×2880，不能沿用会堂默认值。
5. 现有Shadow、Base、WarmLight按职责处理；Ground或Roof只在确有独立显示需求时新增。WarmLight是细节/亮部层，不是现成的动态照明系统，不能自动套色板后宣称发光表现正确。
6. 地面保持在角色下方。Base维持5个语义带：north_range、church、cloister_north、courtyard_and_wings、south_gatehouse；逐带验证纹理采样回到整幅母稿的位置，避免每条带都重复整栋图。
7. 候选绑定脚本/材质随场景交付，确保默认游戏入口和移动Demo都能加载，不把生效逻辑只放在某个试玩启动脚本中。
8. 逐像素比对逻辑掩码，比较12标记、占地、入口和实际通行；素材渲染alpha对比本次认可的视觉几何稿。新材质不要求与旧RGB一致。

如果必须改变视觉外轮廓（挑檐、塔尖等），先明确新的几何稿和逻辑原点，检查周围遮挡；不能简单把旧图拉伸来适配，也不能拿现有图像alpha反推碰撞。

## 4. 路线B：地表、道路和服务区调整

活动环境生成器是`maps/godot/tools/refactor_iserra_map.gd`；`make_iserra_monastery_map.gd`只是兼容入口。前者读取活动地图，保留完整建筑，但删除其他建筑对象子节点、清空六层地表并重建环境，最后直接替换活动场景。

**不要为换贴图直接运行它。** 手工添加的树石/服务屋/道具会被重建覆盖。需要更新环境时，先把需要保留的改动写入生成源，并在隔离工程副本或已修改为显式候选输入/输出的工具上生成。当前工具的OUTPUT/STAGED写死，并没有现成的`--out`参数。

更新院地/前院/山路/两侧服务区时，保留地图接口、完整建筑、所有标记和统一YSort，验证道路与2×3测试车需要通行的范围。重建候选成功且差异可解释后，才替换活动地图。

## 5. 路线C：开放室内或重分屋顶

目前spec虽有roof材质标记，但视觉只有Shadow/Base/WarmLight，不能据此声称已有可隐藏屋顶或可进入教堂。

开启室内前问清要开放哪些房间、采用同图室内还是SceneDoor、是否保留当前中庭路线。再依次改平面/房间solid与walkable、门、碰撞、独立Roof、遮挡区域和交互。先做一个房间闭环，再扩展全院。单改enterable=true或删除碰撞不构成完整实现。

此路线单独立结构功能版本，不能放进“保持玩法不变”的贴图版本混合交付。

## 6. 验收路径

本轮新版本至少截取：全院、南门近景、门内中庭、东西两翼、教堂前、侧边服务区、南下山道；同一机位/缩放分别记录新旧外观。

- 南门两格通道可过、墙阻挡、中庭仍露天；实际走过门楼前后和各遮挡带。
- 12标记位置/作用不漂移；灯火不把整座地图变亮，阴影只出现一次。
- 默认MainHighlandMap与移动Demo均加载新版。Demo出生(45,74)，南出口offset=43/width=4连接M05；默认入口的出生/功能不由Demo配置替代。
- 如果未执行路线C，明确写“未新增室内与自动屋顶”，不把会堂行为当作修道院已有行为。

## 7. 活动版本切换与回退

推荐保留活动地图路径`iserra_monastery_highlands.tscn`稳定，把已通过的候选场景内容指向唯一版本材质资源后再替换。这样默认入口与Demo继承关系继续成立；发布后仍要两处分别验证。

不要只覆盖PNG而漏掉绑定脚本、Shader或源几何稿。若修改building.spec或重建Prefab，检查生成器是否会清掉手工材质；把绑定落实为可重现步骤，不能靠运行时偶然缓存。

记录环境生成器的下次重建行为：它保留当前完整建筑实例，仍需验证该实例的材质绑定随保存保留。回退按本次文件清单恢复地图、相关绑定/逻辑与引用；保留新原图，不删除其他地图素材。
