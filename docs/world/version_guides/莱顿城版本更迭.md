# 莱顿城版本更迭操作指南（Codex）

先读[通用流程](README.md)。现有八区布局由slice.json驱动；新建筑美术按会堂方法制作，城市规划和关卡约束继续保留。

## 1. 认清活动版与样段

| 文件/入口 | 职责 |
| --- | --- |
| maps/leyton/slice.json | 八区布局、道路、水体、建筑条目、出生、出口、城门/墙梯 |
| maps/leyton/graybox_map.gd | 读取布局，生成地表、碰撞、建筑与道具 |
| maps/leyton/viewer.gd | 玩家/测试车、切图、安全落点、门禁、墙顶层 |
| maps/leyton/scenes/m01…m08.tscn | 仅选择map_id，主要布局不在这些小场景中手画 |
| maps/godot/tilesets/urban_rework_v1.tres | 当前共享地表，修道院也引用 |
| assets/maps/leyton/basic_materials_v1/atlas.png | 运行时补入的基础材质 |
| assets/maps/leyton/urban_rework_v1/ | 当前住宅Pattern等；共享替换可影响多区及修道院 |
| maps/leyton/street_sample_v3/layout.json | 独立32×32街坊样段数据，不是当前M02 |
| dev/leyton_world_demo/world.json | 九图Demo与M05北出口覆盖，不是全城主布局 |

当前M01/M02/M03/M04分别31/34/43/28条建筑占地，17/14/27/10件独立装饰；占地条目不等于完成建筑美术。尺寸分别96×80、88×80、96×88、96×80；M05/M06为88×72，M07为96×80，M08为96×72。值属于2026-10-05基线，不作为未来版本固定验收数量。

已有完整结构：M04货运石桥`leyton_cargo_bridge`，条目rect=[42,59,12,11]；M07西门楼`leyton_west_gatehouse`，rect=[85,32,11,16]。M07门洞gate=[85,37,11,6]，不是建筑总占地；保持地面与墙顶层语义分离。

## 2. 保留的城市设计与拓扑

- 城内M01—M04砖石铺装，院地较暗；城门内侧城市铺装、外侧农田/草地，不把全城变回草地。
- M01保留公共广场与河道；M02连续街面、围合院落、曲折主路和生活动线，主车道6米、支路3—4米；不能用均匀矩形住宅填空代替街坊设计。
- M03保留贫民区密集棚屋、救济/登记/水井/焚尸服务及消防净空；M04保持市场仓储、货运桥和河岸功能。
- 四门身份与农业/难民/物流/军用路径保持；河流不通航，水体与水门不可当普通通路。
- 马车当前只是2×3格固定测试占位体，不代表转向、会车或NPC交通已完成。npc_spawns、event_anchors、patrol_routes仍是预留数据。

```text
修道院 ↔ M05 ↔ M02 ↔ M01 ↔ M03 ↔ M06
                       ├ ↔ M04 ↔ M07
                       └ ↔ 抽象住宅区 ↔ M08
```

城市单独入口为14条有向连接；移动Demo加修道院后16条。M01↔M08的抽象住宅路程不能改成物理相邻而不确认。slice.json的M05北出口仍关闭指向world:north，只有Demo通过world.json临时开放到修道院。其余未制作世界出口维持关闭。

## 3. 每次只做一类版本

| 类型 | 改动源 | 必须保持 |
| --- | --- | --- |
| 地表/材质 | 唯一版本纹理、TileSet和明确引用 | 每格通行、道路、水岸、出口和碰撞 |
| 建筑外观 | 某个结构/Pattern的灰盒、材质、绑定 | 该条目rect、锚点、已定路径和门禁 |
| 街坊布局 | 候选slice文档中的指定地图 | 未授权城区及跨图连接；保留批准的主通路 |
| 桥/城门功能 | 对应Building、gate/wall_walk/stairs及控制逻辑 | 地面/墙顶隔离、安全切换、门禁状态 |

优先做一个指定街坊或建筑，提供差异清单后再扩展。不能以“美术更新”名义一次替换全部八区。

## 4. 从候选布局到新外观

1. 从当前slice.json复制候选文档，保留未修改地图条目；记录各图可通行掩码、出生、出口、门禁三态和依赖哈希。
2. 利用graybox_map.gd的`layout_document`导出属性，在候选场景显式指向候选JSON。候选要做跨图验证时，审验控制器/world配置也要指向整组候选场景，不能只改当前一图、邻图仍偷偷加载活动版。
3. 选择要替换的structures条目及其rect，按48px尺度做几何稿；在旧布局上走通人和车后制作分层材质。
4. 完整Building用prefab字段；加载器会断言Prefab地基与rect大小相同。保持锚点变换，前后遮挡与角色处于正确YSort域。
5. Pattern目前由`map_object_placer.gd`拼出`assets/maps/leyton/urban_rework_v1/<pattern>.tscn`，并按rect缩放。**pattern字段不是任意资源路径。** 如需版本目录，显式扩展加载规则或使用隔离的已支持资源名并验证，不能写一个新路径期待自动生效。
6. 避免非等比缩放使门窗和纹理比例变形。新材质以本对象灰盒画布确定采样尺度，不把屋顶平铺纹理当作完整建筑交付。
7. Prop按scene/cell摆放，独立碰撞避开出生、门口和车路。一个共享Pattern/TileSet若被修道院也引用，纳入修道院回归。
8. 候选数据/材质/场景三者一致后才替换活动引用；运行时生成的TileMap单元不是规范源，不手改缓存来“保存布局”。

## 5. 如何使用街坊v3

运行`preview_street_v3.bat`或`street_sample_v3/review.tscn`：WASD走、C人/车、Tab总览、V美术/灰盒、R复位。这里V对照美术；九图Demo用T切地表，会堂用C，不能照抄按键。

v3借鉴的是连续街面、院落和通行方法。它的32×32布局不能直接替换88×80的M02，map.gd还有自己的结构/屋顶绘制逻辑。迁入M02时先画清映射范围、路网接点与院门，再把批准的街坊设计适配到M02候选数据和资源；保留M05/M01出口、出生、主车路和既有设施身份。

若只是全城新材质，不必先迁移v3。若任务要求布局优化，先说明采用哪个样段范围。v3两处院门/墙垛及复杂屋顶掩码仍需核对，不视为已完成整区。

## 6. 禁止误用的入口

- `tools/prepare_atlas.gd`是从旧三图扩到八图的一次性迁移，并检查maps.size()==3。当前八图不要重跑，也不要删保护条件。
- `slice.atlas.staged.json`和archive中的旧布局不是活动源，不用来覆盖slice.json。
- `rework_v2`和planning看板中的旧数量、路线描述与验证次数须按当前源码复核；“当前三图”“M02宽直路”等是过时文字。
- 已淘汰的均匀填楼/旧模型生产命令不作为本次生成步骤；技术遵循新手册。

## 7. 验证矩阵与命令

| 范围 | 至少验证 |
| --- | --- |
| 八区布局 | 八图出生、启用出口往返，整个人/车占位可达 |
| 四门 | 开放/宵禁/封锁，站在门洞时的安全保护，状态跨图保持 |
| 墙顶 | E上下墙梯，墙顶与地面互不混用，墙顶不能跨图 |
| M04/M07 | 货运桥/护栏/水体、西门层高和巡逻道，结构尺寸不漂移 |
| M02样段扩展 | 连续街面、院落门口、6米主路、指定2×3车路、步行巷 |
| Demo | 修道院↔M05及全部16条方向，返回不立即回传，关闭目标门时留在安全源图 |
| 美术 | 地表接缝/重复、灰盒alpha、内部纹理、角色前后遮挡、单次阴影和屋顶行为 |

完整现有回归入口：

```powershell
Set-StrictMode -Version Latest
& 'C:\游戏\maps\leyton\tools\validate.ps1'
```

脚本目前执行13个检查：leyton、atlas、world_demo、bridge、gatehouse、gatehouse_art、surface、basic_materials、urban_rework、godot_map_pipeline、building_pipeline、map_pipeline_phase_one、script_compile；日志写maps/leyton/qa。先备份旧QA，逐项确认失败数和退出码。街坊v3不在该13项内，修改它另跑：

```powershell
$godotExe = 'C:\1\Godot_v4.7.1-stable_win64_console.exe'
& $godotExe --headless --path 'C:\游戏' --script maps/leyton/street_sample_v3/check.gd
```

正式替换前，适配或新增本次候选的逐格逻辑/轮廓检查；仅旧场景测试通过不足以证明候选通过。test_leyton_world_demo目前只对project.godot执行canonical_before哈希断言，并不保护slice/修道院的全部文件，要独立保存本次快照。

GPU入口：`maps/leyton/tools/run_atlas_capture.ps1`、`dev/leyton_world_demo/tools/run_capture.ps1`、`maps/leyton/street_sample_v3/capture.ps1`。它们启动后台进程并返回PID，输出各自qa目录；记录启动时间、等进程结束、核对新报告和截图，不把PID返回当作验收成功。已有同类进程时先查命令行/日志，不重复启动。

## 8. 切换活动版

保留目标文件路径稳定，发布前逐图比较候选slice与当前slice，确认只有任务允许的地图/字段变化。新材质采用版本路径，更新明确的资源引用；共享加载器改动要验证八区、v3及修道院相关调用方。

默认project.godot仍指向修道院；莱顿只在审验入口加载。除非任务明确要求，不把“莱顿版本发布”理解为修改游戏默认主场景或接管存档。

发布后从BAT重走九图和相关门禁，再记录活动revision。回退时恢复slice、资源引用及本次修改的共享代码集合；仅退贴图而留新版布局可能造成尺寸断言或门口不匹配，必须按清单整体核对。
