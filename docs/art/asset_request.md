# 素材需求单：何时提、怎么提、提什么

写代码/做地图时发现「缺素材」，不要停在那里，也不要自己糊一张看不出风格的图顶上去 —— **填一张需求单**。
本文是提需求的唯一入口；填好的需求单存 `docs/art/requests/<日期>-<主题>.md`（本目录下）。

**当前规格：俯视 2D · 48×48 像素 · 黑暗奇幻**，完整规格见 **[style_guide.md](style_guide.md)**
（比例尺 48px=1 米、75/20/5 氛围、三套色板、视角/光照、材质阶梯与色相、自动拼接语义、命名）。
需求单里的"规格"一栏请直接引用该文档的对应小节。

- 素材入库与现状：`assets/dark48/README.md`（48px 当前规格）；旧素材仅可作参考，不得接入运行时地图
- 许可与署名：`assets/来源与许可.md`
- Tile / 小物件怎么接入地图：`docs/world/map_pipeline.md`
- 城堡等大型结构怎么生成资产包并封装场景：`docs/world/building_pipeline.md`
- 示例（填好的需求单，48px 规格）：[requests/2026-09-13-water-and-bridge-tiles.md](requests/2026-09-13-water-and-bridge-tiles.md)

## 1. 先分类：Tile、小物件还是大型结构

任何地图美术需求都必须先选定资产类别。分类看的是**复用方式和逻辑边界**，不是只看图片像素有多大。

| 类别 | 适用对象 | 需求单必须写清 | 后续管线 |
| --- | --- | --- | --- |
| **Tile（图块）** | 地面、道路、岸线、可重复墙段、自动拼接地形 | 单格规格、邻接/拼接规则、变体、`tag`、`solid` | TileSet / `map_pipeline.md` |
| **小物件（Prop）** | 树、岩石、箱子、路牌、火盆等独立摆件 | 网格占地、透明底、锚点、是否阻挡、接地阴影 | 单张透明贴图进入 TileSet / `map_pipeline.md` |
| **大型结构（Building / Structure）** | 城堡、修道院、要塞、庄园、巨型遗迹等完整空间 | 功能、房间、入口、网格 footprint、视觉出血、分层、碰撞与遮挡 | 完整建筑资产包 + 独立 Godot 场景 / `building_pipeline.md` |

**判定门槛**：只要对象拥有完整建筑轮廓、多个房间/入口、独立内部通行或大面积碰撞，就归为大型结构。城堡等大型建筑必须先生成**完整建筑设计**，禁止为了迁就 TileSet 而把最终成图随意切成几十或上百块 Tile。真正需要复用的墙段、地板和门可以另立 Tile 需求，但它们是通用构件，不是被拆碎的整座建筑。

## 2. 三句话流程

1. **先找**：`assets/` 里有没有现成的（第 3 节有找法）。
2. **找不到 → 填需求单**（第 4 节模板），写清类别、规格、语义、许可、验收。
3. **素材到手后按第 8 节接入**；大型结构改走 `building_pipeline.md` 的完整流程。

## 3. 提需求前的自查（不做完这三步的需求单会被退回）

| 自查 | 怎么做 | 结论 |
| --- | --- | --- |
| 1. 项目里已经有了吗 | 看 `assets/` 分类目录（`图格-地面/` `图格-水面/` `图格-道路/` `图格-植被树木/` `图格-围栏篱笆/` `图格-障碍物/` `图格-高地泥泞/` `图格-雪地荒漠/` `hex_切片图格/` `其他/`）与 `assets/原包下载/` | 有 → 直接用，不用提需求 |
| 2. 能复用/裁切/重着色吗 | 48×48 素材可以按格复用；灰白石材、黄绿草地这类只差色调的，可以先重着色 | 能 → 提「重着色」小需求或直接用 |
| 3. 能先占位吗 | 只缺**美术表现**、不挡玩法时，用色块/复用同类图块占位，把玩法先跑通 | 能 → 先占位，需求单降优先级（P2） |

**什么必须先提需求**：缺的图块会影响玩法判定（通行、地形类型）、地图画不出来、或者临时占位会被玩家直接看到。

## 5. 本项目的规格（当前：48px 黑暗奇幻）

### 5.1 Tile 与小物件（地图用，规格最明确）

| 项 | 要求 |
| --- | --- |
| 比例尺 | **48 px = 1 米**；一张 48×48 图块 = 1 m² |
| 单块尺寸 | **48×48**（多格道具 96×96 = 2×2）；不要 47/50px 这类非整数网格 |
| 地面材质 | **四边无缝**（首末行/列逐像素相同）；满幅材质，**无物体、无地平线、无光照方向、无边框** |
| 视角 | 地面 = **正俯视正交**；道具/角色 = **高角度 3/4 俯视 + 左上主光 + 1px 描边 + 接地阴影烘焙** |
| 底色 | 地面不抠底；道具/角色透明底 PNG。若用洋红键控请写明 `#ff00ff` |
| 色板 | 地图环境用 `map_env`（32 色）、角色用 `char`（39 色）、图标/UI 用 `souls`（24 色），**三条线互不通用** |
| 明度与色相 | 必须明确落在材质阶梯的哪一档（草 47.5 / 枯草 61.8 / 泥土 82.9 / 碎石 86.9 / 石砖路 115.1）与哪个色相家族（95° 绿 / 45° 黄 / 24° 红棕 / 30° 低饱和暗黄 / 215° 冷灰） |
| 语义 | 每块图块必须给出 `tag`（ASCII 语义名）+ `solid`（能否通行）+ 一行中文说明 |
| 自动拼接 | 若做地形过渡，按 `auto_<补丁>_over_<底材>_<四邻掩码>_v<变体>` 命名，**16 配置 + 2 变体**，语义见 style_guide 第七节 |
| 追加规则 | 新素材**新开文件或追加在未使用的位置**；不要重排已经进入 TileSet 的素材（会让已画好的地图画错） |

### 5.2 角色 / 道具图标 / UI / 音频

| 类型 | 尺寸 | 备注 |
| --- | --- | --- |
| 角色精灵 | **48×96**（1×2 格） | 4 方向 × 4 帧；四帧**共用同一条地面线**（底边对齐格子下沿） |
| 对话立绘 | 96×128 | 不抠底 |
| UI 头像 | 48×48 | 抠底 + 描边 |
| 角色展示卡 | 144×216 | 带背景 |
| 道具图标 | 64×64 | 抠底 + 1px 描边 |
| UI 元素 | 48×48 / 64×32 / 96×64 | 面板 / 按钮 / 角饰 / 符文徽章 |
| 音频等 | 无全局成文规格 | 需求单第 2 节写清格式/采样率/时长/循环点，并给出参照文件 |

数据接口字段见 `assets/README.md`（`icon` / `art` / `animation` / `portrait`，走 `core/art/art_loader.gd`）。

### 5.3 大型结构

大型结构的“尺寸”必须拆开填写，不能只报一张 PNG 的宽高：

| 尺寸/范围 | 定义 |
| --- | --- |
| `footprint` | 基于 48px Tile 网格的逻辑占地，单位是格；决定放置、越界和占用 |
| `visual` | 分层贴图的实际像素尺寸；允许因屋檐、塔尖、阴影等大于 footprint |
| `collision` | 独立的碰撞掩码或矩形；不等于 footprint，也不从视觉 alpha 自动推断 |
| `occlusion` | 屋顶/前景遮挡区，供进屋隐藏屋顶和 Y 排序使用 |

贴图必须分层导出，至少提供 `base` 与 `roof`；有独立前景、阴影、发光或动画时继续拆层。交付物不是一张合并大图，而是完整源设计、透明分层 PNG、逻辑掩码、metadata 和可实例化的 Godot 场景。详见 `docs/world/building_pipeline.md`。

## 6. 验收（收到素材后逐条查）

1. 尺寸/网格：与规格一致（图块类：48×48 或 96×96，对齐，无半像素）。
2. 无缝（地面类）：环绕接缝色差 ≤ 图内基准 ×1.25。
3. 透明底/背景：无残留底色、无水印、无 JPEG 压缩噪点。
4. 氛围：用 `maps/godot/tools/preview_map.gd` 出图后看 COMPOSITION —— 整图应落在**深 75±6% / 浅 20±6% / 亮 ≤5%**；
   单张材质另看明度档位与色相家族是否与第 5.1 节一致。
5. 风格：与 `assets/dark48/` 现有素材并排看，描边粗细、明度、饱和度、视角一致。
6. 语义表：每块图块都有 tag、solid、说明（缺了就没法进 TileSet，等于没交付）。
7. 许可：作者/来源页面/许可/署名文本齐全，能写进 `assets/来源与许可.md`。

任一条不过 → 退回需求单，写明缺哪条；**不要先把不合规素材合进项目再说**。

## 7. 会被直接退回的常见原因

- 规格缺失：没说尺寸/网格/透明底/许可中的任何一项。
- 尺寸或比例不对：不是 48 的整数倍；地面不是无缝满幅；道具没抠底/没接地阴影。
- 色板串线：用 `souls`（冷蓝灰金属）画地图环境，或用 `char` 画地面。
- 亮色乱撒：把高光均匀撒在材质上（"到处都在闪，所以哪里都不闪"）。
- 交付的是成品图而不是可用素材：`.jpg`、带背景、带水印、把整张地图当素材。
- 把城堡等大型结构随意切成几十块 Tile，或只交一张合并图而没有透明分层、独立碰撞和场景封装资料。
- 缺语义：只给图片，不说哪块能走、哪块是什么（图块类需求）。
- 混入玩法需求：需求单只谈素材；玩法规则变化走对应模块的 `docs/<模块>/rules.md`。

## 8. 交付后怎么接入（Tile / 小物件类）

```bat
:: 1) 素材放进 assets/dark48/ 对应分类目录（多格道具记得说明占几格）
:: 2) 更新 assets/dark48/README.md 与 assets/来源与许可.md
:: 3) 在 maps/godot/tilesets/dark48.spec.json 里追加条目（items：tag/name/solid/file[/size]）
C:\1\Godot_v4.7.1-stable_win64_console.exe --headless --path C:\游戏 --import
C:\1\Godot_v4.7.1-stable_win64_console.exe --headless --path C:\游戏 --script maps/godot/tools/build_tileset.gd
:: 4) 打开 Godot，在 maps/godot/scenes/<地图>.tscn 里刷（选块对着 *_图块对照表.html）
::    手绘完跑一次边缘修正：… --script maps/godot/tools/autotile_fixup.gd -- res://maps/godot/scenes/<地图>.tscn
:: 5) 校验
… --script tests\map\test_godot_map_pipeline.gd
:: 6) 在 docs/development/changelog.md 追加一条记录
```

其他类型（图标/立绘/UI）的接入：放进 `assets/dark48/` 对应目录 → 在 `content/` 对应数据文件里填
`icon`/`art`/`portrait` 路径 → 跑对应模块测试（例：`tests/card/test_card_logics.gd`）。

大型结构不执行本节的 TileSet 步骤；按 `building_pipeline.md` 完成透明处理、分层、独立碰撞与 Prefab 生成，最后把 `.tscn` 作为一个对象实例化到地图。

## 9. 需求单怎么写才快

- **一次一个主题**：别把「水面图块 + 主菜单 UI + 战斗音效」塞进一张单子。
- **清单越具体越好**：与其写「要一些水」，不如写「浅水 3 个变体（可通行）、深水 1 个（阻挡）、河岸 8 向邻接 8 块」。
- **能拆批就拆批**：P0 先做能跑起来的那几块，表现类的留给 P1/P2。
- **带上参照**：写清参照文件路径，比一千字描述风格都管用。
