# 剩余重制卡牌机制归纳（2026-10-05）

## 范围与口径

- 来源为 `content/cards/[ADKB]001..075.json` 中当前标记 `design_only` 的 165 张牌；原文和来源行号已保存在卡牌 JSON。`remaining_mechanisms.json` 逐牌记录原文、来源和候选机制家族；运行 `build_mechanism_inventory.py` 可随启用进度重建。
- 一张卡可能同时涉及几个家族，下表计数不可相加。家族匹配用于盘点，不表示卡牌已可执行。启用前仍需逐字核对费用、目标、时序、选择、触发及离场规则。
- 可调用、已验收的机制登记于 `content/cards/mechanics.json`；尚未实现的机制保留在本文和索引中，避免被导入器误当成可用逻辑。

## 实施依赖与顺序

1. **确定性基础条件与状态**：先做可在现有结算器内准确判定的快照、阈值、单目标状态和状态层数操作；每项写入 `mechanics.json`、`conditions.json`（如适用）及规则文档，再测边界。`target_block_at_play_at_least` / `target_block_at_play_at_most` 已供 A022/A047/K034 调用，B032 等后续牌仍需其他机制。
2. **战场事件与空间接口**：统一先移后攻、攻击后移、强制位移结果、六边形多目标/直线。地图选择与战斗结算共享同一合法目标检查。
3. **玩家选择与牌区事务**：已完成随机实体牌转移、整手洗回重抽，以及从抽牌堆或弃牌堆随机展示、玩家选一张置顶的完整事务；接着扩展多选、牌堆排序、弃牌、保留和临时复制品的生命周期；不得用随机自动选择替代玩家选择。
4. **持续触发系统**：以战斗事件登记能力牌、下次效果和每回合次数；反击接在敌方普通 Attack 完整结算后的单一窗口。
5. **组合与逐牌接入**：只在依赖机制均已通过测试后，让导入器按机制模板生成效果，并将对应卡牌设为 `supported`；每批回归后重建索引。

## 当前机制工作边界

- 出牌前 Armor 快照条件已通过独立测试，并接入完整牌文可表达的 A022/A047/K034；其余牌保持 `design_only` 直至全部依赖可执行。
- 出牌前硬性条件已支持生命百分比阈值，K067 在付款前拒绝不合法目标；基础随机牌区事务已供 A024/D071 调用。
- `choose_from_pile` 已供 A017/A054/D027/K026/K060/D059/A063/A019/B071/D034/K025/A033/A055/K058/D055/D075/A074/K074/A041 调用；`inspect_top_cards` 已供 A006/A029/A036/A068/A042 调用；`choose_hand_discard` 已供 A010/A037/A060 调用。支持卡组/牌库只读来源、不同 ID 抽样、顺序多选去向、主动弃牌、顶牌排序及选择后续行。A038 还需弃牌堆多选到底部；A051 还需要“先完成移动再查看”的时序接口。
- `标记`、`迟缓`、`脆弱`、`破绽`、`鼓舞` 尚无可执行 BuffData 规格；先明确强度、衰减、触发和叠层规则，再登记为可调用机制。
- 165 张的候选家族映射为自动盘点；复杂牌需逐张人工确认具体组件和顺序。
