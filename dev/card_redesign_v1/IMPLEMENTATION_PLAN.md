# 重制卡牌落实步骤

## 当前基线

- 来源：根目录四份重制卡组文档，300 张设计牌。
- 当前运行时已支持 123 张；177 张为 `design_only`（2026-10-05 顶牌可选弃置批次后）。最新逐牌剩余索引以 `remaining_mechanisms.json` 为准。
- 后续改为机制优先：先查 `REMAINING_MECHANISMS.md` 与 `remaining_mechanisms.json`，实现并验证公共机制，再让卡牌导入器调用。候选机制标签不等于可运行支持。
- 每次从文档原文出发，只有费用、目标、效果和限制全部可执行时才改为 `supported`。

## 批次顺序与完成标准

1. **盘点与分组**：由 `build_mechanism_inventory.py` 对所有 `design_only` 牌生成逐牌候选机制索引；人工核对每张牌的原文、时序和依赖规则。
2. **通用规则**：先更新 `docs/card/rules.md` 与 `content/cards/mechanics.json`，再扩展 CardData / CardDB / BattleManager / EffectSystem。出牌前验证必须先于费用、生命和手牌变动。
3. **机制先行**：每个公共机制独立登记、实现并通过边界/结算测试后，导入器才组合机制；只把规则完整对应的卡设为 `supported`。未完成的随机选择、目标选择、范围、Power 或状态效果仍留在 `design_only`。
4. **交互与回归**：同步手牌费用或锁定提示；对新增牌执行真实战斗断言，并跑卡牌、战斗、存档测试及主场景/战斗场景无头加载。
5. **交付记录**：更新 supported/design_only 数量和 `WORKLOG.md`，明确下一批缺口。完整设计池的目标是 300 张逐批可玩。

## 本批：卡莎精密的目标条件降费

状态：已实现，待后续批次继续扩展其他精密条件。

- K009：目标中毒，本牌费用 1→0；造成 5 伤害。
- K010：本回合对该目标使用过 Drug，费用 2→1；造成 10 伤害并令目标直接失去 2 生命。
- K028：目标虚弱，费用 1→0；造成 5 伤害并令目标直接失去 2 生命。
- K029：目标毒层数至少 5，费用 2→1；造成 11 伤害并令目标直接失去 3 生命。

验收：条件满足与不满足时费用正确；费用不足不改变手牌或生命；目标换成另一敌人不继承 Drug 条件；状态不被降费消耗；回合切换清空本回合记录；旧卡不受影响。
