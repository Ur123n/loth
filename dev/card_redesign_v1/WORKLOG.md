# 卡牌重制 v1.0 工作记录

## 目标与来源

- 来源：根目录《卡牌重制设计说明_v1.0.md》与四份《完整卡组_重制v1.0.md》。每人 75 张，共 300 张。
- 本轮不制作卡面；所有新 JSON 的 `icon`、`art`、`animation` 为空。
- 生成器：`dev/import_card_redesign_v1.py`。重新运行会更新 `content/cards/[ADKB]001..075.json`。
- 规范来源：`docs/card/rules.md`、`dev/card_redesign_v1/REMAINING_MECHANISMS.md`；可复用的已验收机制以 `content/cards/mechanics.json` 为准。

## 当前结果（2026-10-05）

- 300 张数据已生成，ID 无缺号、无重复。费用、Load、稀有度、目标、原文、标签与来源行号入库。
- 122 张牌标为 `supported`：A 31、D 24、K 37、B 30；178 张复杂牌仍标为 `design_only`，CardDB 跳过。
- 机制数据库现含 15 类效果、20 类条件、2 类修正、3 类出牌规则；122 张已启用牌的 `mechanism_ids` 与实际效果、条件及费用规则校验一致。
- 改为机制优先：已从当前 178 张 `design_only` 生成逐牌候选机制索引 `remaining_mechanisms.json`，归纳为 12 个重叠机制家族，路线见 `REMAINING_MECHANISMS.md`。出牌前目标格挡（Armor）快照的 ≥ / ≤ 阈值条件已复用到 A022、A047、K034。
- 已完成按模板组合卡牌、Armor 快照、击退、生命支付、随机实体牌转移、洗回重抽和出牌前硬性条件。近期接入 A024、D071、K067。
- 最新一批新增 `choose_from_pile`：从抽牌堆/弃牌堆无放回随机展示实体牌，由玩家从文本弹窗选一张置于抽牌堆顶。A017、A054、D027、K026 完整接入；其余牌因多选、筛选、复制品或后续效果仍保留设计状态。
- 选择事务期间出牌、移动、结束行动均被锁定；空候选直接结束，未选中牌保持原位置。针对 Node2D 父节点修正弹窗按视口定尺寸；弹窗按钮及回调测试通过。
- 本批扩展 `choose_from_pile` 的基础类型、基础费用、标签、出牌历史过滤，支持选中牌加入手牌与仅选中实体下次打出消耗。K060、D059、A063 全文接入。出牌事务可在选择时暂停，提交后从下一项效果续行，结束后才触发出牌记录、离场和 `card_played`；空候选同步续行。连选弹窗不会被旧选择回调误关。
- 又接入完整列出 Basic、当行动临时费用覆盖/降低及手牌原位保留；A019、B071、D034 全文接入。选择弹窗支持长列表滚动。
- 应用户要求审计实体抽牌：普通抽牌确实按有序数组末尾取牌，弃牌堆只在抽空时洗回；修复了开战卡组与生成牌多槽共享同一 Resource 的问题，随机转移改为按槽位移走，显式随机化无注入 RNG 的战斗。牌顶、牌底与牌数守恒已测试。
- 本批新增 `inspect_top_cards`：暂存真实顶牌，依次由玩家选牌入手、弃置，再按牌顶到牌底指定剩余顺序；不足张数仅处理现有实体，最后一张自动归位。A006、A029、A036、A068 全文接入；选择后续行与锁定沿用现有事务。Godot 新脚本类初次加载需要 `--editor --import` 更新类索引，本次已完成。

## 后续具体工作

1. 按 `REMAINING_MECHANISMS.md` 的依赖顺序先完成通用机制；可运行机制登记到 `content/cards/mechanics.json`，未实现项只保留在计划索引。

3. 下一步按全文规则继续接入可复用选择牌：可选弃置、牌库/当前牌组来源、多选去向、临时复制品及其生命周期；之后处理公共状态规则、位移和迪马斯反击。任何未实现条款仍保留 `design_only`。

## 路径与风险

- 原有 `dev/card_import/generated/` 为旧版 v0.1 生成物，本次没有修改。
- 根目录项目原有大量未提交修改；本次卡牌逻辑修改集中在 `core/card/`、`core/effect/`、`core/battle/`、`ui/battle/`、卡牌导入脚本与对应测试。
- 生成器是 300 张重制 JSON 的唯一编辑入口；修改机制或模板后运行导入器及 `build_mechanism_inventory.py`，再跑目录、逻辑、战斗、存档和场景检查。
