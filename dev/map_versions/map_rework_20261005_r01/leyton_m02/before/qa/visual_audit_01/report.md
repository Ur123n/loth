## 方法与证据边界

- 审阅者为当前会话的多模态模型，使用view_image直接读取11张图像；没有另外调用独立外部视觉模型，不构成第二模型交叉验收。
- 输入为已归档的实际Godot截图，包括八区汇总、v2地表近景、M04石桥、M07门楼及上下层对照、六件物件验收图。没有用提示词或测试数字代替读图。
- 这是归档渲染图审查，本轮未重新启动游戏或重跑导航/碰撞。部分截图HUD仍为三图时期版本，因此不得据此判断当前HUD或八区连接存在回归。
- 输入副本、原路径、修改时间、SHA256及尺寸写入evidence_manifest.json；问题框坐标写入findings.json。index.html可显示/隐藏定位框，源PNG保持原样。
- 判断依据：项目style_guide中的正交地表、高角3/4立件、平行投影、48px/m、稀少亮色、轮廓与通路辨识。静态图不能证明连续运动、真实尺寸、动态闪烁、导航完整性或精确纹章细节。

## 优先问题

### R01 · P1 · 地表高频纹理抢占注意力

证据：evidence/surface.png，区域约(40,163,710,466)，同时参看bridge.png及props.png。

草、土、碎石路都由密集细碎斑点构成，近景缺少低细节区域。道路的亮度区分仍成立，问题是背景内部细节过多，小物件的暗边容易融入其中。

建议优先降低草地和路肩细节对比，保留较大的色块变化。复验要用相同镜头、相同摆放点的原尺寸对照，不能只看放大的单张材质。

### R02 · P1 · 门洞下层角色完全消失

证据：evidence/ground_probe.png与upper_probe.png，同一XY、相同构图，角色区域约(581,303,117,91)。

地面截图看不到角色，上层截图能看到。它支持既有分层遮挡逻辑正在工作，但从可玩性反馈看，受控角色进入覆盖区后缺少视觉追踪。该问题不是“墙顶层级错误”的判定。

建议加受遮挡轮廓或局部透明反馈。复验应连续走过门洞，确认角色始终可追踪，且墙顶/护栏关系不被破坏。本轮静态图不证明遮挡持续多久。

### R03 · P1 · 煤筐与木桶暗背景适配不足

证据：evidence/props.png，煤筐草地格约(17,819,129,114)，木桶草地格约(440,380,128,115)。

煤块和桶身暗侧与草地亮度接近，密集草纹进一步削弱轮廓；相同物件在泥地、石路上的识别更容易。

优先给这两件物品设置清理过的摆放地面；确需草地使用时，减少邻近纹理或增强有限轮廓，不建议整件高亮化。复验使用原尺寸与实际镜头。

## 优化与用途确认

- **R04 / P2 石桥桥跨感**：bridge.png中桥面宽于接入道路且南北铺台较长，视觉更像大平台。保留既定12×11逻辑占地，先用桥台、朝南窄立面、局部水面遮蔽和入口接缝增强跨河结构；不能仅凭视觉意见缩窄已验收车道。
- **R05 / P2 门楼高差线索**：gate.png中的门洞地面与上层巡逻道材质/明度接近。护栏已提供边界，但交叉处的立面、落影和桥洞边缘仍可加强。与R02不同，这是结构的空间阅读问题。
- **R06 / P2待确认 公告栏用途**：props.png中的公告栏显得低矮。高角投影的图像高度不等于真实身高，故这里只记录设计疑问；若是街头站立阅读设施，先做加长立柱的比例稿，再决定是否修改精灵和接地点。

## 已知交付缺口，单独记录

- 门洞红/黄矩形、橙色墙梯、绿色出口条及水门占位属于当前诊断/灰盒表现，阻止最终美术交付；它们不是本轮新发现的生成主体损坏。
- M01太阳神像和多数城区建筑仍为占位块；农田缺最终纹理与作物层，NPC尚未形成画面密度。不能以石桥、门楼和六件物件完成推导城区完成。
- 门楼小徽记在图中尺度过小，无法核实无门黑塔、三道麦穗和八芒星是否精确符合设定；不做通过判定。
- 归档画面中的白色玩家与橙色车体为测试占位，不能用其身体轮廓精确评价建筑真实比例。
