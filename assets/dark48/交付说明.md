### 05_角色动画 的帧序

`{角色}_walk_{方向}_{0..3}.png`，方向 `s`=正向（面向镜头）`n`=背向 `w`=侧向左 `e`=侧向右。
四帧的语义是 **接触 → 过渡 → 接触 → 过渡**，第 4 帧整体上移 1px 做出走路该有的上下起伏。
四帧**共用同一个缩放与同一条地面线**，所以直接按帧播放不会抖（底边极差 1–3px）。

## 二、给引擎的对接要点

1. **调色板**：三套色板是**互不通用**的三条线，见 `10_色板`
   | 色板 | 用在哪 | 色数 |
   |---|---|---|
   | `souls.json` | 道具图标 / UI / 场景 | 24 |
   | `map_env.json` | 地图地形 / 道具 / 过渡 / 拼接集 | 32 |
   | `char.json` | 两个角色的全部形态与动画 | 39 |

   除描边色 `(12,10,16)` 之外，所有像素颜色都能在对应色板里找到
   （色板归属实测：地图 100%、角色 95%、图标 94.3%，越界的就是那个描边色）。
   若引擎按调色板索引工作，把 `(12,10,16)` 并进色板即可全部归零。

2. **地图地形**：`06_地图地形` 的 5 张是**四边无缝**的（环绕接缝色差实测 0.0）。
   直接平铺可得到无接缝的地面，但同一张反复平铺会有周期感 —— 破周期请配合 `08` / `09`。

3. **地形过渡怎么用**：约定**每条边整条都是一种材质**，材质边界只在 tile 内部过渡。
   于是"相邻两格共享的那条边，两侧材质天然一致" ⇒ 拼接必然连续。
   * `08_地形过渡/<材质对>/` 里 `_n` `_e` `_s` `_w` 分别表示"该方向邻格是另一种材质"，
     不带后缀的那张是**中心格**（四邻都是另一种材质）；
   * `_v1` `_v2` `_v3` 是三个变体，**只能整张替换使用，不要对边 tile 做随机翻转**
     —— 翻转会把边界条带翻到错误的一侧。

4. **16 配置自动拼接集**（推荐优先用它）：`09_自动拼接集/<材质对>/`
   文件名后缀是四邻配置，如 `_nesw` 表示北东南西四个邻格都是补丁材质、`_none` 表示都不带。
   每个配置 2 个变体，用它们可以拼出**任意形状**的地形边缘（含凹角与 T 形口），
   不再像 4 直边 tile 那样在凹角处裸切。**注意**：角像素的对角歧义是 16 配置集固有的
   （完全消除需要 47 配置集）；实测把偏差限制在单角像素，可接受。
   本套的边约定验收**全部通过**，真邻接接缝与源 tile 自身环绕基准完全一致。

5. **角色动画的地面线**：四帧的主体底边对齐在同一行（y=89，画布 96 高），
   脚下另有 3 层柔和落影。摆放时按**底边对齐格子下沿**即可。

6. **接地阴影**：`07_地图道具` 与角色精灵都带半透明落影（落到画布底边前 1–2px）。
   若引擎自己画影子，直接忽略半透明像素即可。

## 三、已知情况（交付时如实标注）

### 已完成并复核通过

* 地图地形五张的明度阶梯 **51.4 / 62.7 / 81.1 / 86.7 / 93.1**（可一眼分辨可走区域），四边无缝；
* 16 配置自动拼接集 128 张：覆盖度 16/16 × 2 变体 × 4 对，**边约定全通过**，
  真邻接接缝 0.0 == 源 tile 环绕基准 0.0；
* 多材质演示地图的画面级占比 **78.2 / 21.5 / 0.2**（目标 75/20/5，容差 ±6%）；
* 角色白发读得出（银白高光占比 8.6%–43.2%）；
* 无贴边、无底边黑条（全量扫描通过）；
* **行走帧每一帧都是单一连通域**（32/32）—— 腿和胯都连在身体上，见下节。

### 关于"腿部与胯部像素缺少"的修复

**现象**：早期版本的行走帧里，腿像是浮着的、胯像被挖空。

**根因**：**胯部与大腿内侧在源稿里本来就很暗、接近背景色**，而抠底容差是 22 ——
那圈像素被当成背景挖掉，腿就从身体上脱落。实测 `elise_walk_w` 第 1 帧被切成 **5 块**
（最大块只占全身 48%），`elise_walk_s` 第 0 帧被切成 **7 块**（最大块 36%）。

**修法（两步）**：
1. 行走帧的抠底容差从 22 降到 **8**（原稿背景确实是近黑、边带中位亮度 0–9，不会放进背景）：
   该帧 5 块 → 1 块，胯 **+64px**、腿 **+97px**、躯干 +50px，而且**只增不减**
   （同位置比对"旧有新无"的像素为 0）；
2. 再加一道**桥接**：把仍脱落的腿/手臂用 1px 直线接回主体，并清掉孤立碎点
   （`tools\pixelize.py` 的 `bridge_components`）。

**结果**：`05_角色动画` 的 **32 帧全部是单一连通域**，不透明像素从 500–800 提升到 1000–1900。

**代价（复核指出，已在文档中标注）**：
* 容差调低后靠近底色的背景噪点也会被留下一点（个别帧多出十几个碎点，桥接步清掉大部分）；
* 边缘的半透明过渡被砍掉，斜边更硬、锯齿更明显；
* 各帧"修复强度"不一致 —— 鲍德温侧向那几帧本来就连续、只补回 24px，
  所以放进同一循环时他会比艾莉丝暗一档。**若要逐帧播放，建议按角色分别微调一次亮度。**

### 仍有保留

1. **正/背方向的行走只有 2 个可区分相位**（侧向是完整的 3 相位）。
   原因不是管线：正视时两条腿被身体挡住、背视时看不到前后关系，**这个信息在视角里本来就不存在**。
2. **两个角色的明度不同**（艾莉丝精灵 58.7 / 鲍德温 119.2，约 2 倍）——
   这是**原稿本身的差异**，不是后处理造成的；后处理已证明无法在不破坏色彩的前提下拉平。
3. **48×48 头像的可读性仍是弱项**：已经用像素级手修补上了蒙眼布、银白头发、
   荆棘冠尖刺、两个对称眼窝、头部浅色绷带（详见 `docs\06` 6.4 的对照表），
   但脸部仍是几块平涂、身体部分与头部风格有断层。
4. **只有数值验收、没有视觉验收的**：16 配置自动拼接集、四方向行走帧。

## 四、可复现性

每个素材都能追到"哪份原稿 + 哪套参数 + 哪个工具"：

```powershell
$py = "C:\comfy ui\ComfyUI\venv\Scripts\python.exe"
cd C:\美术素材制作

# 交付目录本身
& $py tools\build_delivery.py

# 复核（只读）
& $py _qa\measure_now.py             # 全量测量 + 贴边/黑条扫描 + 行走帧一致性
& $py _qa\verify_autotile_now.py     # 16 配置集三项验收
```

原稿在 `assets\raw\`，参数清单在 `specs\*.json`，各轮的判定与失败原因在 `docs\05_工作日志.md`。
